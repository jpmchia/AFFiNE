# Timeline View & Editor

Add a new "Timeline" section to AFFiNE that streams individual blocks (not whole docs) from opted-in documents, in chronological order, with click-to-expand editing — built on top of existing but under-used BlockSuite per-block metadata, AFFiNE's doc-properties system, and the existing All-Docs/Journal/collection-rules/peek-view infrastructure.

## Confirmed scope (from clarifying Q&A, including follow-up decisions)

- **Granularity**: block-level, not doc-level. Every block that carries `BlockMeta` (paragraph, list, image, attachment, bookmark, callout, code, table — i.e. **all** content blocks with metadata, no curated subset) inside an opted-in doc appears as its own timeline entry.
- **Opt-in mechanism**: a new doc property `includeInTimeline` (boolean). Settable per-document, bulk-appliable to all docs in a folder, and inheritable from a template doc (so docs created from that template default to opted-in).
- **Folder bulk-apply semantics**: applying to a folder is a **one-off mutation** on its existing doc descendants, **plus** it persists an `includeInTimelineDefault` flag on the folder node so that any doc **subsequently** linked/created into that folder inherits the setting automatically at link-creation time. Not a live/retroactive rule re-applied continuously — only new links trigger inheritance.
- **Ordering field**: a new **per-block** property `displayInTimelineAt` (timestamp), independent from `meta:createdAt`/`meta:updatedAt` so blocks can be manually repositioned in the stream without disturbing real audit timestamps.
- **Default/fallback source**: one workspace-level setting (`createdAt` \| `updatedAt`) serves two purposes — (1) what new/updated blocks get auto-stamped into `displayInTimelineAt`, and (2) the fallback timestamp used at query-time for blocks that predate this feature and were never stamped.
- **Editing**: click-to-expand. Timeline renders read-only excerpts by default; clicking an entry opens it editable in place/peek, not simultaneous live inline editing for every row.
- **Navigation**: new top-level sidebar item ("Timeline"), new route, alongside All Docs / Journals.
- **Scale strategy**: ship the client-side aggregation (walk all opted-in docs' block trees) first; explicitly design the data model so a later iteration can swap in the shared indexer without a schema migration.
- **Feature flag**: a new, dedicated flag (not reusing `enable_block_meta`), spanning both the AFFiNE-side `FeatureFlagService` and BlockSuite's own `FeatureFlagService`/`BlockSuiteFlags` (same dual-registration pattern `enable_block_meta` uses).

## Implementation plan

### 1. Data model: doc-level `includeInTimeline` property
- Add `includeInTimeline: f.boolean().optional()` to `docProperties` in `packages/frontend/core/src/modules/db/schema/schema.ts`.
- Add `includeInTimeline: { filter: 'is' | 'is-not' }` to `WorkspacePropertyTypes` in `modules/workspace-property/types.ts`.
- Register a built-in property entry in `modules/workspace-property/constants.ts` (`BUILT_IN_CUSTOM_PROPERTY_TYPE`), mirroring the `template` entry.
- Add `setIncludeInTimeline`/read helpers alongside `setPrimaryMode`/`getPrimaryMode` in `modules/doc/entities/doc.ts` and `entities/record.ts`.
- Add UI toggle component `components/workspace-property-types/include-in-timeline.tsx` mirroring `template.tsx`, surfaced in the doc-info property panel (`modules/doc-info`).
- Add filter/groupBy/orderBy providers under `modules/collection-rules/impls/{filters,group-by,order-by}/include-in-timeline.ts` (mirrors `template.ts` triplet) and register in `modules/collection-rules/index.ts`, plus a `system-property-types`/`workspace-property-types` entry for the property-panel/filter UI (mirrors the `template` entries in `components/system-property-types/index.ts`).
- No change needed for propagation: `DocsService.duplicateDoc`/`duplicateFromTemplate` (`modules/doc/services/docs.ts`) copy all properties not in `removedProperties`, so template → doc and doc → doc duplication inherit `includeInTimeline` automatically.

### 2. Bulk-apply + folder-level default for `includeInTimeline`
- Extend the `folders` schema (`modules/db/schema/schema.ts`) with `includeInTimelineDefault: f.boolean().optional()`, meaningful only on nodes with `type === 'folder'`.
- Add `FolderStore.setIncludeInTimelineDefault(folderId, value)` / read via existing `watchNodeInfo`, and expose `includeInTimelineDefault$`/`setIncludeInTimelineDefault` on `FolderNode` (`modules/organize/entities/folder-node.ts`).
- Add a context-menu action "Include folder in Timeline" on folder nodes (`desktop/components/navigation-panel`, organize section) that, on activation:
  1. Sets `includeInTimelineDefault = true` on the folder node (persists the default for future links).
  2. **One-off**: recursively walks current descendants (`children$`/`sortedChildren$`, recursing into sub-folders, filtering `type === 'doc'`) and calls `docsService.list.doc$(id).setProperty('includeInTimeline', true)` for each existing doc.
- Hook `FolderNode.createLink` (and/or `FolderStore.createLink`) for `type === 'doc'`: after creating the link, check only the **immediate parent folder's** `includeInTimelineDefault`; if `true`, set `includeInTimeline = true` on the linked doc. This covers both "create new doc inside folder" and "drag an existing doc into folder" — both call `createLink` today. **Confirmed**: no ancestor walk beyond the direct parent — a doc in a sub-folder does not inherit a grandparent folder's default.

### 3. Workspace setting: default `displayInTimelineAt` source
- New `modules/timeline/store/setting.ts` + `entities/setting.ts` (`TimelineSetting`), modeled exactly on `modules/template-doc/{store,entities}/setting.ts`, storing `defaultDisplayAtSource: 'createdAt' | 'updatedAt'` in the workspace `settings` key/value table.
- **Confirmed placement**: surface this as a new `SettingWrapper` (e.g. `TimelineSetting` component) inside the workspace **Preferences** tab — `desktop/dialogs/setting/workspace-setting/preference/index.tsx` (`activeTab === 'workspace:preference'`), rendered alongside the existing `<TemplateDocSetting />` (see `preference/template.tsx` for the exact `SettingWrapper`/`SettingRow` pattern to copy). The `enable_timeline` feature flag toggle itself needs no separate placement — as an `AFFINE_FLAGS` entry it's automatically listed on the general **Experimental Features** tab (`desktop/dialogs/setting/general-setting/experimental-features/index.tsx` renders `Object.keys(AFFINE_FLAGS)` generically).

### 4. Block-level `displayInTimelineAt` metadata (BlockSuite)
- Extend `BlockMeta` type in `blocksuite/affine/model/src/utils/types.ts` with `'meta:displayInTimelineAt'?: number`.
- Add the field (default `undefined`) to each block schema's `props` factory that currently mixes in `BlockMeta` — i.e. **all** of them: `paragraph-model.ts`, `list-model.ts`, `image-model.ts`, `attachment-model.ts`, `bookmark-model.ts`, `callout-model.ts`, `code-model.ts`, `table-model.ts` (all under `blocksuite/affine/model/src/blocks/*`). No block-type filtering — every content block with metadata participates.
- Update `isBlockMetaSupported` in `block-meta-service.ts` to also check for `'meta:displayInTimelineAt'`.
- Extend `BlockMetaService`'s `_onBlockCreated`/`_onBlockUpdated` (or add a sibling `TimelineMetaService`) so that when a block is created/updated **and its doc has `includeInTimeline === true`**, `meta:displayInTimelineAt` is stamped from `meta:createdAt` or `meta:updatedAt` per the workspace's `TimelineSetting.defaultDisplayAtSource`, but **only if not already manually set** (never overwrite a user-repositioned value).
- `BlockMetaService` lives in the `blocksuite/` package and has no direct access to AFFiNE's `DocsService`/doc properties — it currently gets external info via a `Provider` pattern (see `WriterInfoProvider` in `user-service.ts`). Introduce an analogous `TimelineConfigProvider` (interface: `isDocIncludedInTimeline(docId): boolean`, `defaultDisplayAtSource(): 'createdAt' | 'updatedAt'`) implemented and injected from `frontend/core`'s BlockSuite view-extensions wiring so BlockSuite core stays decoupled from AFFiNE-specific doc properties.
- **Dedicated feature flag `enable_timeline`**: register in both places, mirroring `enable_block_meta`'s dual registration:
  - `blocksuite/affine/shared/src/services/feature-flag-service.ts`: add `enable_timeline: boolean` to `BlockSuiteFlags` (default `false`), gates the BlockSuite-side stamping logic.
  - `packages/frontend/core/src/modules/feature-flag/constant.ts`: add `enable_timeline: { category: 'blocksuite', bsFlag: 'enable_timeline', displayName: ..., description: ..., configurable: true, defaultState: false }` in `AFFINE_FLAGS`, which also gates the AFFiNE-side UI (nav item, doc-property toggle, folder actions).
- Add a manual edit path: a small UI (e.g. a date/time field in a block's context/hover toolbar or the timeline entry itself) that calls `model.props['meta:displayInTimelineAt'] = newValue` directly, bypassing the auto-stamp logic.

### 5. Cross-doc timeline aggregation service
- New module `packages/frontend/core/src/modules/timeline/` (mirrors `modules/journal/` shape): `TimelineStore` (raw data access), `TimelineService` (derived `LiveData`), `TimelineSetting` (from step 3).
- `TimelineStore.includedDocIds$`: `LiveData.computed` over `docsService.list.docs$`, filtering `doc.properties$.value.includeInTimeline === true` and non-trashed — same shape as `JournalStore.allJournalDates$`.
- `TimelineService.entries$(range?)`: for each included doc, open/subscribe its BlockSuite store (via `DocsService`/`store.getBlockSuiteDoc`), walk the block tree, and for every block with `BlockMeta` lacking `meta:displayInTimelineAt`, compute the fallback `defaultDisplayAtSource === 'createdAt' ? meta:createdAt : meta:updatedAt` and **persist it by writing `model.props['meta:displayInTimelineAt']`** (backfill-on-read, confirmed — not a purely computed/ephemeral fallback), so the value becomes a normal, user-repositionable timestamp going forward. Collect `{ docId, blockId, flavour, displayInTimelineAt, excerpt }`, merged and sorted into one `LiveData` array.
- Excerpt generation (**confirmed: reuse, don't rebuild**): extract the per-block text-extraction branch already embedded in `getPagePreviewText` (`components/page-list/use-block-suite-page-preview.ts` — `block.text?.toString()` for text blocks, `[flavour]` placeholder for non-text blocks like image/attachment/bookmark) into a standalone `getBlockPreviewText(block): string` helper, used by both the existing whole-page preview and this new per-block timeline excerpt.
- **Scale note (Phase 1 now, Phase 2 planned)**: this "open every included doc and walk its blocks" approach is simplest and fully client-side/offline-capable but won't scale to large workspaces — ship this first. Design `TimelineService`'s public shape (the `{docId, blockId, flavour, displayInTimelineAt, excerpt}` entry type and the filtering/pagination API) so it can be backed by a different data source later without changing consumers. **Phase 2 (follow-up, not in this iteration)**: extend the shared indexer — add `displayInTimelineAt` (Date) and `includeInTimeline` (Boolean) fields to the `block`/`doc` tables in `packages/common/nbstore/src/storage/indexer/schema.ts`, populate them wherever blocks are currently indexed, and query via `indexer.search$('block', ...)`/`aggregate$` like `DocsSearchService` does today; also touches the backend indexer (`packages/backend/server/src/plugins/indexer`) for cloud-synced workspaces.

### 6. Timeline UI: route, page, sidebar entry
- Add `{ path: '/timeline', lazy: () => import('./pages/workspace/timeline') }` to `workbenchRoutes` in `desktop/workbench-router.ts`.
- New `desktop/pages/workspace/timeline/index.tsx`, structured like `all-page.tsx`: `ViewTitle`/`ViewIcon`/`ViewHeader` (date-range filter, maybe a compact calendar like the journal panel) / `ViewBody` rendering a virtualized chronological list of timeline entries grouped by day (reuse `group-definitions.tsx`'s date-bucketing pattern), each entry showing a compact read-only preview (icon by `flavour`, excerpt text, doc title/link, time).
- Add `TimelineButton` to `components/root-app-sidebar/index.tsx`, modeled on `AppSidebarJournalButton`/`AllDocsButton`, linking to `/timeline`.
- Click behavior: open the entry via `PeekViewService`/doc-preview peek (passing an `EditorSelector` targeting the specific `blockId`, same mechanism used by `docLinkClicked`'s `open-in-center-peek` in `detail-page.tsx`), landing the user directly on that block for editing, rather than a full navigation.
- Entry-level control to manually edit `displayInTimelineAt` (drag within the list, or a small date-time picker) per step 4's manual edit path.
